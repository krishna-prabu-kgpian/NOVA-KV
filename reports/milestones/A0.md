## Design decisions and invariants

Decisions are recorded in full in `docs/decisions.md`. Those a reviewer should confirm:

- **D-003** — the header declares the whole A+B+C API from the start so the unmodified
  generator (which needs a complete `Transaction`) compiles. Unimplemented parts report
  failure; they never report success.
- **D-004** — `Snapshot` is the nested type `KVStore::Snapshot`.
- **D-005** — no `noexcept` on Appendix A functions other than the two printed on `Snapshot`.
- **D-006** — pimpl for private state (one immutable pointer indirection; revisit with data).
- **D-007** — one library per sync policy from the same sources.
- **D-008** — release is `-O3 -g -DNDEBUG`; `-DNDEBUG` is an addition to blueprint §9.3.
- **D-001 / D-002** — spec documents stay at the root; the generator moved to `supplied/`.

No concurrency invariant (INV-01…INV-15) is exercised yet because no concurrent code exists.
The only invariants A0 establishes are structural: the supplied files are immutable (checksum
gate) and the public signatures are immutable (compile-time gate).

## Known limitations and source ambiguities

Limitations of this milestone:

1. **The store does not store anything.** Every Part A–E requirement is unimplemented.
2. `workload_gen.h` is a transcription from a PDF; whitespace is not claimed to be identical
   to an instructor file that was never supplied.
3. `cmake` exists only as a project-local install. A machine without cmake and without
   network access to PyPI cannot build until cmake is installed some other way.
4. Tested with one compiler only (GCC 15.2). No clang.
5. The three sync variants are identical placeholders; only their build wiring is verified.

Environment blockers for later milestones (not for A0):

6. **perf is unusable** without root (`perf_event_paranoid = 4`). Blocks the Part A profiling
   deliverable (A2) and Part D flame graphs until changed. Fix requires the user:
   `sudo sysctl kernel.perf_event_paranoid=1` (or `-1`), or running the captures privileged.
7. **FlameGraph scripts are not installed.** Needs approval to fetch
   `github.com/brendangregg/FlameGraph`.
8. Governor is `powersave` on a laptop; benchmark variance may be high. To be recorded and,
   if the user agrees, changed to `performance` for the measurement campaigns.

Source ambiguities confirmed while reading the PDF and the generator (details and line
numbers in `docs/assignment_contract.md` §4):

9. The generator finishes loading before any reader starts, so it cannot by itself produce
   the "one background writer active throughout" measurements of Parts A and D.
10. About 99.9 % of the generator's random-branch lookups miss with default parameters.
11. `use_join` in the generator is a single-call index probe, not the C.2 join.
12. **OPEN / INSTRUCTOR:** C.2 demands exactly one `Snapshot` for a join over two `KVStore`
    instances. Unresolved; no claim is made.
13. D.2 needs a maximum stall; `WorkloadResults` has no such field.
14. The blueprint cites 151 lines for `workload_gen.cpp`; the supplied file has 150
    newline-terminated lines. The SHA-256 is the reference.

Not yet confirmed by the user: the blueprint §14 pre-coding checklist (default parameters and
the §2.2 error contracts). A1 will implement the §2.2 contracts as written unless told
otherwise.
